下面先给出一个“把可执行程序改成动态库（.so）”的总体思路和注意点，确认思路没问题后我们再细化到具体的 CMake 改动。

1.  确定你的需求
    
    -   你目前的可执行文件里有 `main.cc`，很可能所有的处理逻辑都写在了这个可执行入口里。
        
    -   如果要生成一个 .so，那么： a) 你需要把真正要对外调用的功能抽象成一套函数接口（API）<br>b) 把这些 API 的实现（例如原来在 `process.cc` 或者 `whisper.cc` 中的函数）编译进动态库<br>c) 通常会把 `main.cc` 中的演示或测试逻辑剥离出去，由上层调用者（另外的可执行程序、脚本等）来驱动。
        
2.  修改 CMake 的总体步骤<br>a) 改用 `add_library(${PROJECT_NAME} SHARED …)` 而不是 `add_executable`<br>b) 把不需要进动态库的 `main.cc` 从 sources 列表里去掉（如果你仍想保留测试程序，可额外再建一个可执行 target，链接这个 .so）<br>c) 确保开启 Position Independent Code（PIC），但 CMake 对 SHARED target 默认会加 `-fPIC`，一般无需手动指定<br>d) 把原来 `target_link_libraries(${PROJECT_NAME} …)` 的逻辑保留，同样链接依赖库到 .so<br>e) 修改 install：安装的是库文件到 `lib/` 目录，头文件（如果有）到 `include/`
    
3.  可能的目录结构和输出
    
    -   ${INSTALL\_PREFIX}/lib/librknn\_whisper\_demo.so
        
    -   ${INSTALL\_PREFIX}/include/ （放你对外公开的 .h）
        
    -   ${INSTALL\_PREFIX}/model/ （模型文件拷贝不变）
        
4.  如果你还想同时保留一个示例可执行文件：
    
    -   在同一个 CMakeLists.txt 里，既可以 `add_library(rknn_whisper_demo SHARED …)`，<br>又可以额外写一个 `add_executable(rknn_whisper_demo_demo main_for_demo.cc)`，然后 `target_link_libraries(rknn_whisper_demo_demo rknn_whisper_demo)`
        
    -   把原来的 `main.cc` 重命名为 `main_for_demo.cc`，示例程序里调用 .so 中导出的 API
        
5.  接口设计建议
    
    -   在 `process.cc` 或者新建一个 `rknn_whisper.h` 中声明几组对外函数，比如
        
        ```cpp

          int whisper_init(const char* model_path);
          int whisper_run(float* input, int input_len, char* output, int max_out);
          void whisper_release();
        }
        ```

```cpp
extern "C"
```
